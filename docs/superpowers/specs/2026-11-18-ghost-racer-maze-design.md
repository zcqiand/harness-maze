# harness-maze 合法幽灵竞速——设计文档

> 2026-11-18 人裁收口（brainstorming 产出）。书 ch9《迷宫探险》配套仓（ch16 程序化生成 v2 蜂体，措辞待统一）。

## 意图与为什么

把 harness-maze 第一步换栈（Godot→React）并写成完整可玩的迷宫竞速。突出点只有一个：**「合法幽灵」**——每张迷宫记下你的最快走线存成幽灵，下一局你的影子与你同跑；排行榜上的幽灵全部经过断言认证：寻路合法性断言+存档校验双闸保证幽灵是一条合法走线，作弊在结构上不可能（改存档造出来的穿墙/瞬移幽灵被断言当场拒收并指出违规步号）。断言不是法官而是「认证机构」。书 ch9 教学核心（结构化地图规约/寻路合法性断言/无存档校验）全部是幽灵认证的构成件：地图规约=认证的输入契约，寻路断言=认证的判定器，存档校验=认证的防篡改层。ch9 practice 原题（手改地图制造非法改动被断言抓住）由「幽灵被拒收」自然覆盖+独立测试钉死。

## 目标

- **骨架换栈**：删 Godot 工程件（project.godot/scenes/scripts），按 2048/snake 同款 React 骨架重建（React React 19 + Tailwind 4 + TS strict + Vite + vitest，零新增依赖），`data/levels/` 地图契约保留演化
- **完整可玩迷宫竞速**：网格迷宫（起点→终点），方向键/WASD 离散步进+按住连走,实时计时 HUD（毫秒），触屏四向按钮
- **合法幽灵**：完赛走线落幽灵槽（每图一条，PB 单槽），下一局同图开局影子与你同跑（半透明影子按记录时间戳滑行）；成绩面板列每图最佳与幽灵在位状态
- **幽灵认证双闸**：①走线合法性断言（起点格出发/终点格收尾/每步相邻/不穿墙/步长恒 1）②存档校验（checksum+加载时全量重验，非法即拒收该幽灵回退「无幽灵」态不白屏）——防篡改测试显式覆盖书 practice 厬题（篡改走线→拒收+报违规步号）
- **种子化关卡包**：包号 N 种子化无限包，每包 5 张（尺寸 11→19 阶梯），简单生成器（recursive backtracker）；成绩与幽灵按（包号,图号）记档
- **结构化地图规约**：`{name, grid, start, goal}`（0/1 现网格+起终点），规约合法性枚举成文（docs/conventions/map-spec.md），level_001.json 演化为规约样例
- 本地成绩册：按（包号,图号）分段的最佳时间+幽灵在位状态，读侧守卫前置（2048/snake 两仓教训，第一天就带）

## 关键设计裁定（builder check 前我方裁定，用户可否决）

1. **走线离散格步进**：每键一步（相邻格），按住以固定间隔连走；幽灵回放按记录时间戳插值滑行（数据离散、渲染连续）；换向即时响应，不做输入缓冲队列
2. **认证双闸职责分离**：走线合法性断言判定「走线是不是合法路径」（结构面）；存档校验判定「存储没被改过」（防篡改面）。时间作弊不判——时间修短=合法速通范畴
3. **撞墙=阻挡不判负**：竞速无死亡语义；撞墙原地不动+轻微墙闪反馈，步数不增时钟不停
4. **幽灵单槽**：每图只存最快一条；破 PB 旧幽灵退休新上位；平局先到先得。首局无幽灵=无影子纯计时
5. **关卡包种子化**：包号即种子，同包号永远同 5 张图，确定性可复现——为 ch16 难度规约留好接口
6. 包号→参数推导：`size = 11 + 2 * min(packNo-1, 4)`（11→19 封顶），每包 5 张同尺寸
7. 存档键版本前缀 `hmaze.v1.*`，存档结构含 version 字段
8. 生成器合法性自证：产出每张图必须过规约校验+BFS 可解性断言才落包（ch16 过滤器雏形，本批只做自检不做过滤管线）
9. **起表锚=首输入**（builder check 裁定）：待命态不起表；第一次方向输入同时启动计时器与幽灵回放，两者 t=0 严格同锚——speedrun 惯例，反应延迟不计入成绩，幽灵不会「先跑」
10. **关卡身份=grid 哈希**（builder check 裁定）：每条成绩/幽灵记录钉 `gridHash`（生成器版本无关的内容寻址，同 mold 哈希锁哲学）；加载时哈希不符=旧版关卡**封存**（成绩册可见、标注旧版、不可赛不可记档），不静默拒收——ch16 生成器升级时旧档案平滑共存而非破坏性迁移
11. **存档原子单元：单键整体写+逐条校验**（builder check 裁定）：全部记录存单键 `hmaze.v1.records`（对象，键=「包,图」），写侧整体原子写（双键版本化切换）；校验逐条——每条记录自带 checksum，加载逐条验、坏一条弃一条不连坐（满足「拒收该幽灵」粒度）；容量不设清理策略（记录数=玩家实际游玩量，YAGNI）
12. **checksum 全覆盖**（builder check 裁定）：checksum 覆盖整条记录含 `result.time`——「时间作弊不判」仅指断言枚举五条不含时间物理下界（改短时间的合法存档照赛）；存档被外部改动（含改时间）属防篡改层，拒收。认证断言增第 6 条一致性校验：`result.time === 末步 t`
13. **level_001.json=纯 fixture**（builder check 裁定）：升级为补齐 start/goal 的规约样例，仅供单测与 map-spec.md 引用，不进游戏流（选图只走种子包）——引擎加载层只吃内存规约对象，data/levels/ 无运行时路径
14. **包号合法域 N≥1 整数**（builder check 裁定）：无上界（尺寸公式已封顶 19，N≥5 全是同尺寸异种子包）；非法输入（0/负/非整数）读侧守卫回落选包页不抛错——fail-fast 纪律约束 env/契约边界，玩家输入面走守卫回落

## 视觉方向（builder 落地）

「计时赛 TT」风：深色沥青底+赛道白线网格，幽灵半透明轮廓滑行，HUD 毫秒表+完赛时间差（±s.ms vs PB）；破 PB 瞬时高亮。克制不花哨——个性在「影子在跑」的临场感

## 状态机与语义裁定（builder check 收口）

1. 状态机：选包/选图 → 待命 → running（计时走线+幽灵同跑）→ finished（时间差结算）→ 返回选图
2. 中途放弃：Esc=回选图不计档；running 中换图=同放弃
3. **幽灵不重赛**：影子是历史忠实重放，不阻挡不碰撞不交互——它是你的过去，不是对手实体
4. 幽灵数据={steps:[{t,cell}], result:time}，t=相对开局毫秒；重放=按真实经过时间驱动影子位置
5. 生成器合法性自证：产出每张图必须过规约校验+BFS 可解性断言才落包
